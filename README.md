# 러닝플로우 — 이 약, 더 먹어도 될까? (카메라·판정 버전)

친구의 `learningflow-med-python-revised`를 바탕으로 만든 버전입니다. Python 3.11 이상, 표준 라이브러리만 사용합니다.

## 흐름

1. **오늘 이미 먹은 약**을 카메라로 찍습니다. 여러 개를 찍을 수 있고, 약마다 오늘 먹은 개수를 입력합니다.
2. **새로 먹으려는 약**을 찍고, 이번에 먹을 개수를 입력합니다.
3. 찍은 사진은 서버를 거쳐 **Upstage Studio API**로 보냅니다(`studio_client.py`). Extract 결과의 제품명과 유효성분을 화면에 보여줍니다.
4. 제품명으로 식약처 허가정보에서 후보를 찾고 성분·함량을 대조합니다. 다음 두 경우에만 **자동 선택**합니다. 자동 선택이 틀리면 **다른 제품이에요**를 눌러 직접 고릅니다.
   - 성분·함량이 모두 일치하고 계산이 가능한 후보가 하나뿐일 때
   - 그런 후보가 여럿이지만 제조사까지 맞는 후보가 하나뿐일 때
5. **더 먹어도 되는지 확인**을 누르면 성분별로 하루 합계(먹은 양 + 새로 먹을 양)를 계산합니다. 이 합계를 1일 최대투여량과 비교하고 DUR을 확인해 세 단계로 알려 줍니다.
   - 🔴 **지금은 더 먹지 마세요**: 1일 최대량 초과, 병용금기, 효능군 중복
   - 🟡 **약사에게 확인이 필요해요**: 기준을 못 찾음, 같은 성분 중복, API 조회 실패, 용량주의 대상
   - 🟢 **확인한 범위에서는 문제를 찾지 못했어요**: 위 항목이 하나도 없을 때. 확인하지 않은 항목(복용 간격, 개인 조건 등)도 함께 보여 줍니다.

"먹어도 됩니다"라고 단정하지 않습니다. 조회에 실패하면 문제 없음으로 처리하지 않고 확인 필요로 표시합니다.

## 실행

```powershell
copy .env.example .env      # 키 입력
python main.py              # http://127.0.0.1:8767
python demo_fake.py         # 키 없이 가상 데이터로 흐름 시연 (화면에 '가상 데모 모드' 표시)
python -m unittest discover -s tests -v
```

- 카메라는 `http://127.0.0.1` 또는 `localhost`, HTTPS 주소에서만 열립니다(브라우저 보안 정책). 같은 PC에서 웹캠으로 찍는 프로토타입은 그대로 됩니다.
- 폰 카메라로 찍으려면 HTTPS 배포가 필요합니다. 카메라가 안 되면 **사진 파일 선택**으로 대신할 수 있습니다.

## 필요한 키와 활용신청

| 용도 | API | 설정 |
|---|---|---|
| 사진 분석 | Upstage Studio (Document Agent v2) | `UPSTAGE_API_KEY`, `UPSTAGE_AGENT_ID` |
| 제품 검색·주성분 | 식약처 의약품 제품 허가정보 (data.go.kr 15095677) | `MFDS_SERVICE_KEY` |
| 1일 최대투여량 | 식약처 의약품 성분별 1일 최대투여량 정보 (data.go.kr 15098095) | 같은 키, 별도 활용신청 |
| 병용금기·효능군 중복·용량주의 | 식약처 DUR 품목정보 (data.go.kr 15059486) | 같은 키, 별도 활용신청 |

공공데이터포털 API는 같은 인증키를 쓰더라도 **API마다 활용신청**을 해야 합니다.

## Upstage Studio Agent의 Extract 출력 형식

코드는 Extract 결과가 아래 키 이름으로 온다고 가정합니다. Studio에서 정한 추출 항목 이름이 다르면 제품명을 읽지 못한 것으로 처리됩니다.

```json
{"product_name_raw": "제품명", "manufacturer": "제조사",
 "effective_ingredients": [{"ingredient_name": "성분명", "strength_per_unit": "500mg"}]}
```

## 이번에 바뀐 점

- **카메라 화면**(`static/`): 촬영 → 미리보기 → 분석 → 인식 결과·자동 선택 → 개수 입력 → 목록 추가. 화면을 다시 만들면서 기존 `tests/test_ui.cjs`는 삭제했습니다.
- **자동 선택**(`workflow.pick_auto`): 확실한 경우에만 자동으로 고르고, 애매하면 이유를 보여 주고 사용자가 선택합니다.
- **판정**(`workflow._judge`, `daymax_client.py`, `dur_client.py`)
  - 1일 최대투여량은 경구 행만 사용합니다. 제형별 값이 다르면 가장 낮은 값과 비교합니다.
  - 팀이 검토한 기준을 `verified_rules.json`에 넣으면 API 값보다 먼저 씁니다. 성분코드 대신 `ingredient_name`으로도 지정할 수 있습니다.
- **버그 수정**
  - 제조사의 `(주)`, `㈜`, `주식회사` 표기 차이로 일치 판정이 실패하던 문제
  - `1,000mg`, `500㎎`, `100밀리리터 중` 같은 표기를 읽지 못하던 문제
  - 검색을 많이 하면 확인한 약이 30분 전에 만료되던 문제(기록을 종류별로 따로 보관하도록 변경)
  - 마지막 페이지에서도 "후보가 더 있다"는 경고가 뜨던 문제
- 친구 원본과의 차이는 `docs/카메라판정_변경.patch`에 있습니다. 기존 `docs/` 문서는 이전 버전 설명입니다.

## 실제 키로 꼭 확인할 것

- **1일 최대투여량 API**
  - 확인한 것: 요청주소와 필드(`CPNT_CD`, `DRUG_CPNT_KOR_NM`, `DOSAGE_ROUTE_CODE`, `DAY_MAX_DOSG_QY`, `DAY_MAX_DOSG_QY_UNIT`)는 포털 명세에서 확인했습니다.
  - 확인할 것: 투여경로 값에 실제로 '경구'가 들어오는지, 허가정보의 주성분코드(`MTRAL_CODE`)가 이 API의 `CPNT_CD`와 같은 체계인지. 코드로 못 찾으면 성분명으로 다시 찾습니다.
- **DUR API**
  - 확인한 것: 병용금기(`getUsjntTabooInfoList03`, `itemName`, `mixtureItemName`)만 공개 소스로 확인했습니다.
  - 추정한 것: 용량주의·효능군 중복 오퍼레이션 이름과 응답 필드는 추정입니다. 응답을 보고 `dur_client.py`의 `OPERATIONS`와 `GROUP_KEYS`를 맞추세요.
- **Upstage**: `config_id` 필드와 결과의 `output_text` 필드 이름은 공식 문서에서 확인하지 못했습니다.
- 성인 기준입니다. 복용 간격, 나이·체중·임신·간/신장 기능, 목록에 넣지 않은 약은 판단하지 않습니다.
